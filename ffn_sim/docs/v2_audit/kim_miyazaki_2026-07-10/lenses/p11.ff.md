# FF lens — p11

**Paper:** Miyazaki & Harada, "Go-and-Back method: Effective estimation of the hidden motion of proteins from single-molecule time series," *J. Chem. Phys.* **134**, 135104 (2011). DOI 10.1063/1.3574396.

**One-line verdict for FF:** This is a *statistical-inference / trajectory-estimation* method (recover a hidden protein coordinate x(t) from an observed probe coordinate y(t)), NOT a forward filament/motor/crosslinker force law. It contributes **no new mechanism, force law, or rate constant** to the FF forward simulator. Its only genuine contact with FF is (a) it shares the exact substrate physics FF's integrator already uses — overdamped Langevin with fluctuation–dissipation noise variance 2γk_BT — and (b) it offers an *analysis-side* tool that could sit downstream of FF single-molecule outputs (motor stepping, clutch/bond dwell traces). FF impact is low. I report it honestly rather than inflate.

---

## 1. Mechanisms to adopt

**Nothing to graft into the FF force model.** The paper contains no filament bending law, no motor force-velocity, no Bell-Evans off-rate, no branching-angle scheme, no crosslinker kinetics. Every "model" in it (Model A double-well, Model B tilted washboard) is a 1D toy landscape used to *test the estimator*, not a cytoskeletal mechanism.

The only transferable idea, and it is **analysis infrastructure, not a runtime mechanism**:

- **(Optional, downstream-only) Hidden-coordinate estimator for FF single-molecule observables.** FF already produces the ground-truth trajectories the paper has to *infer* — e.g. a Stam–Hocky myosin head's position on a filament, an integrin/α-actinin clutch's bound-state coordinate, an F₁-like rotary step. So the estimator is not needed to *run* FF. Where it could help: when we compare FF against a *real* single-molecule experiment (probe-particle bead assays: kinesin/myosin/F₁ stepping, optical-trap clutch dwell), the experiment sees only the delayed noisy bead y(t); to compare it to FF's true motor coordinate we would need to invert the bead→motor delay. Go-and-Back is a cheap (>10³× cheaper than gradient descent) way to do that inversion. This is a *validation-pipeline* tool, filed for the day FF is benchmarked against bead-assay data, and does not touch the mechanistic runtime.

Why it does NOT beat any current FF mechanism: it operates on a different axis (post-hoc inference) than any FF force law. There is no substitution.

---

## 2. Force laws / kinetic schemes to port

**None portable to the FF forward model.** For completeness and to prove the assessment, here is the paper's machinery and its (non-)mapping to FF state:

- **Two coupled overdamped Langevin eqs (Eqs. 1–2):**
  `γ ẋ = −∂_x[V_eff(x) + U(x,y)] + ξ`, `Γ ẏ = F(y) − ∂_y U(x,y) + η`,
  with `⟨ξ⟩=⟨η⟩=0`, `Var(ξ)=2γk_BT`, `Var(η)=2Γk_BT`.
  **FF mapping:** this IS the per-particle overdamped equation FF's constrained Leimkuhler–Matthews BAOAB integrator already integrates (drift = −∂U, noise = √(2γk_BT) white). FF thus *already implements* the paper's forward dynamics. There is nothing to port — it is a re-statement of FF's existing substrate at the two-DoF level. The FDT normalization `Var = 2γk_BT` is a sanity cross-check for FF's thermostat, not a new law.

- **Elastic linker U(x,y):** harmonic spring, stiffness k. Trivially the same functional form as any FF bead–bead harmonic bond / clutch tether; provides no new stiffness value (k=160 is in dimensionless model units, not SI).

- **Onsager–Machlup action S (Eq. 5)** and the **Go-and-Back forward/backward ODE pair (Eqs. 11–12, 17–18):**
  `γ ẋ = −G_x(x,y) + v` (forward), `γ v̇ = G_xx(x,y)·v − k_BT·G_xxx(x,y)` (backward),
  with `G ≡ V_eff + U`, auxiliary `v(t)` a deterministic surrogate for the noise ξ, perturbation order i, closure `v_(0)=0`.
  **FF mapping: NONE in the runtime.** This is an *inference/optimizer* scheme (find the most-probable hidden path by minimizing the action), not a simulator time-step. It would only ever run as an offline post-processor on FF or experimental time series. Do not put the OM action or the v-ODE into the FF force kernel.

- **Diminishing-time / relaxation scale `τ_dim ~ γ/G_xx(x_b) = γ/(a₁+k)`:** a boundary-condition-forgetting timescale for the estimator. Not a physical relaxation time of any FF filament network.

## 3. Parameters / rate constants to set

**None.** Every numeric constant in the paper is in **dimensionless model units** on synthetic toy landscapes — not SI, not cell-derived, not registerable to the KB:

| symbol | value | note — why NOT usable in FF |
|---|---|---|
| γ (protein friction) | 2 | model units, not a physical drag; not the ~65 Pa·s cytoplasm |
| Γ (probe friction) | 20 | model units; γ/Γ=0.1 is just the small-parameter for their expansion |
| k (linker) | 160 | model units, not Ferrer link stiffness |
| k_BT | 4.11 | model energy units (they note ≈ pN·nm at 298 K, but it is a scale choice) |
| Δt | 0.01 | model time; unrelated to FF CFL |
| a₁…a₈, A=20, l=1, f=40 | — | fitted/chosen toy-landscape coefficients (double-well, washboard) |
| SD_thermal = √(2k_BTΔt/γ) = 0.2 | 0.2 | correct *form* of discrete-time thermal SD — this is the only equation FF could reuse as a **thermostat unit test** (given γ,Δt,T, the per-step positional SD of a free overdamped bead must equal √(2k_BTΔt/γ)). Value 0.2 is model-unit-specific; the formula is generic. |

The one takeaway: **`SD_step = √(2 k_B T Δt / γ)`** is a legitimate closed-form sanity check for FF's BAOAB thermostat (free-particle limit). It is not a new parameter — it is a validation oracle for equilibrium noise magnitude.

Nothing supersedes any current FF value (k_off0, F_b, stall force, step size, duty ratio, ℓ_p, link stiffness, nucleation rate).

## 4. Network architecture / protocol to reproduce

**No reconstitution geometry, no motility assay, no confinement, no network.** The paper is single-DoF (one hidden coordinate + one probe). There is no filament network, no density, no connectivity, nothing that maps to an FF scenario.

The closest thing to a "protocol" is the **probe-particle bead assay** it presupposes (a large bead loosely tethered to a motor, delayed & thermally smeared relative to the motor): this is context describing *how single-molecule motor data is collected*, useful only as a reminder that if FF is ever validated against bead-assay motor traces, the observable is the *bead*, not the motor head — the delay/smearing must be modeled or inverted before comparison. Not a runnable FF scenario.

---

## 5. Validation targets for FF observables

**No FF-usable measured numbers.** All quantitative results are estimator-performance metrics on synthetic data:

- >10³-fold compute reduction vs gradient descent; ~10⁴× faster action relaxation; converged action −3.04×10⁴ vs −2.91×10⁴ (model units); convergence at order i≈15; BC-forgetting τ_dim≈0.001–0.005; IC sensitivity ~10⁻⁴. — All are *method benchmarks*, not physics.

- The only externally-cited real numbers are other groups' instrument specs and a canonical motor fact, useful only as loose context if FF is compared to bead assays:
  - probe temporal resolution up to **9.1 µs** (Ueno 2010),
  - probe spatial resolution **0.1 nm**,
  - **F₁-ATPase 120° rotary steps** (Noji 1997).
  None is an MCF7/cortex/crosslinker/myosin constant; none is registerable as an FF validation gate.

The single reusable *check*: FF's free-overdamped-bead equilibrium positional SD must equal √(2k_BTΔt/γ) (§3) — a thermostat unit test, not a cell observable.

## 6. Risks / caveats

- **Category mismatch (dominant risk):** this is an inference method for hidden-trajectory recovery, not a mechanistic force law. Adopting anything from it into the FF *runtime* would violate the fine-grained-mechanistic principle (it is an estimator/optimizer, i.e. exactly a post-hoc analysis layer, not particle/bond dynamics). Keep it strictly downstream of the simulator if used at all.
- **Dimensionless toy units:** all constants are model units on fitted double-well / washboard landscapes. Porting any value into FF would inject a magic number with no physical provenance — forbidden by the no-magic-number rule. Do not KB-register any parameter from this paper.
- **1D, single-DoF, purified single-molecule regime:** no network, no cortex, no confinement, no 3D — the opposite end of the scale spectrum from FF's native 38 000-filament cortex. Nothing here is validated at, or transferable to, native cell scale.
- **Model assumptions the authors themselves flag:** position-independent friction γ and time-independent V_eff. Real FF filaments/motors have load- and history-dependent kinetics (Bell-Evans, catch-bonds, non-Markovian turnover), so even the estimator would need extension before touching FF-derived traces.
- **Adaptation without breaking rules:** if we ever benchmark FF single-molecule outputs against real bead-assay data, use Go-and-Back **only** as an offline inversion of the bead→motor delay, run on the *experimental* trace, then compare to FF's already-known true motor coordinate. This keeps the physiological-baseline and native-scale rules intact because it never enters the forward run.

**Net:** File p11 as a *methods/statistical-inference* reference (probe-particle hidden-trajectory estimation). Actionable FF residue is two small, optional items: (1) the free-bead thermostat check `SD = √(2k_BTΔt/γ)`; (2) a shelved offline estimator for future bead-assay validation. No mechanism, force law, parameter, scenario, or gate to adopt.
