# ARCHITECTURE COMPLETENESS AUDIT — is 13/32 enough for a crawling adherent cell? (2026-07-25)

Produced by a Workflow fan-out: 6 independent completeness lenses (epithelial cell biology / load-path
closure / the project's own 10-compartment spec / crawl sufficiency / deformation coupling / an adversary
arguing sufficiency), each attacked by a verifier instructed to refute BOTH the claimed gaps AND the claimed
sufficiencies, then one judge weighting verifiers over mappers.

Standard applied: a gap counts ONLY if it is a mechanical load path a real adherent crawling epithelial cell
HAS and this graph CANNOT express even in principle. Unimplemented, unparameterised, or low-evidence-rung is
NOT an architecture gap. Of ~25 gap claims raised, three survived.

Commissioned under the PI priority set 2026-07-25: mechanical connectedness is the gate, parameter magnitudes
are explicitly NOT.

## 1. VERDICT IN ONE PARAGRAPH

**Yes — 13 components is complete, and 32 connectors is sufficient for a mechanically complete, crawling, adherent MCF7-like cell, short of one genuinely missing component pair and two missing edges in families that already exist.** Six lenses ran; not one produced a 14th state owner that survived its verifier, and both structures the PI named by hand are expressible today with no new edge: the cortex crumpling as one object is component-internal (crosslink percolation + its own WCA self-contact, `aleph/engine/forces_manifest.py:260-262`), and lamellipodium → ECM remodelling → forward motion closes edge-for-edge (`lamellipodium_membrane_contact` `contracts.py:344-350` → `lamellipodium_nascent_fa` :364-370 → the one composite `alpha2beta1_collagen_series` clutch :273-283 → `ecm_crosslink` :433-438 → `ecm_far_field_anchor` :439-444 → `world_boundary`). Of the ~25 gap claims raised, exactly one is a component pair that appears nowhere in the graph and whose interaction is *sign-unavailable* (the cortex cannot push the nucleus); two more are missing instances in first-class families, one of which the project's own SoT plan already specifies and never promoted into the tuple. None of the three blocks either PI example, and none requires a parameter magnitude the project does not have. **The binding constraint is therefore not the architecture: `AUDIT_AC_ENGINE_2026-07-25.md:62` measures "3 of 13 components and 1 of 32 connectors" bound in the only composed build, "**Net: 2 of 32 connectors dispatched**. It has never been stepped on CUDA," and 30 declared-but-undispatched edges dominate any conceivable 33rd.**

## 4. LOAD PATHS THAT EXIST BUT SUM TO ZERO

This section changed my ranking more than any gap did.

1. **The only registered global acceptance criterion is identically zero for a crawling cell.** `GlobalCellLedger` carries `reaction_resultant_d`, `traction_resultant_d`, `force_resultant_d`, `work_d`, `mass_d`, `topology_counts_d`, `balance_residual_sq_d`, `balance_ok_d` (`ledger.py:154-174`), and `assemble_balance` gates on `|reaction + traction|²` (:329-336). A self-propelled inertialess cell is force-free: that residual is zero whether it crawls or sits still. There is **no moment channel and no centroid channel** (grep for "moment" in `ledger.py`: no matches) — while the ECM contact protocol already promises one: `ecm_world.py:346` "Contribute contact force, **moment**, work, and stale-generation counts." **Consequence: "the cell moves forward" is currently ungateable.** This is the single most dangerous zero in the system and it is an observable, not a connector.
2. **`membrane_erm_cortex` transmits exactly zero at the physiological baseline.** The ERM law is a unilateral tensile Hookean tether, and "a compressed / broken / resting tether is force-free" (`erm_cortex_connector.py:34`). Hence `RESTING_BASELINE_DIAGNOSIS_2026-07-23c.md:132-138`: "inert while the ERM is force-free" / "the membrane turgor cannot be balanced by cortex form-finding through a force-free ERM (**proven inert**)". The declared edge exists and carries nothing at rest. Surviving gap #2 is exactly its fix.
3. **`nmii_cortex_motor` is net-zero by construction and its substrate route is conditional.** Myosin contracting a closed shell is an internal actuator: net force zero (correct). Its only tangential route to ground is 2-hop via `sf_cortex_transient` (:284-289), which `LOAD_PATH_PLAN.md:104` declares "optional, dynamic" with finite lifetime. So the engine's best-evidenced connector (heads 0→85.24% bound, γ_total 3.7234 at 70,686 filaments per the audit table) contributes substrate traction only when a ventral SF population exists *and* that bond is bound. The graph's structural guard against a repeat of the ff/ cancellation is real but thin: `nmii_*_motor` endpoint_role_b is "live **polar** actin material coordinate" (:401) so contraction follows filament polarity rather than being centripetal-by-construction, and front/rear adhesions carry **distinct** chemistry cards (`actin_talin_integrin` :276 vs `actin_talin_integrin_nascent` :369, :395).
4. **The crawl dipole can still net-cancel at runtime with every edge force-real.** The recorded deceleration mechanism is ECM-side, not graph-side: "the cell densifies/contracts the local collagen symmetrically (recruit grows +185→+230 nm) and embeds in a symmetric well, opposing the residual polar force → v decays" (`_historical/MDA_MB_231_MIGRATION_ROOTCAUSE_2026-07-14.md`, §4). Far-field anchoring fixes momentum *accounting*, not the well. This must become a run-level gate, not a contract change.
5. **Rear release can be zero-displacement.** Today the only disassembly channel is bond rupture: every component is declared `has_events=False` (`contracts.py:191-196`) and the audit records "**No state-owner class exists anywhere in `ac/engine`**" for `focal_adhesion`. A ruptured rear clutch may immediately re-nucleate through the nascent-FA edges — which is precisely the recorded ff/ failure ("the rear edge merely unbinds (zero force) instead of retracting the body forward").
6. **The mass analogue.** `surface_porous_transfer` and `sf_cytosol_transfer` carry endpoint role "porous-fluid transfer stencil" only (:260-261, :331-332), whereas the protrusion transfers carry "porous drag and **G-actin transport** stencil" (:361-362, :388-389), and CHEMICAL_FLUX is used 0 times. Sustained protrusion drains a monomer pool that cortex disassembly cannot refill.
7. **Correct zeros, not defects:** turgor (Young–Laplace, one pressure owner delivering traction through two boundaries), `lamellipodium_cortex_seam` (internal Newton pair), and the whole-cell force-free condition itself.

## 5. WHAT SUFFICIENCY ACTUALLY DEPENDS ON

**ARCHITECTURE completeness — the PI question. Answer: sufficient, modulo ≤3 one-line `ConnectorContract` additions (32→35), none of which needs a parameter magnitude.** Component set: complete. Connector set: short by one inexpressible pair (nucleus↔cortex contact), one plan-mandated instance (membrane↔cortex contact), one untracked instance (nmii↔cytosol). Both contact laws are force-free at the physiological gap, so they add no sourced magnitude beyond a numerical exclusion stiffness derivable from the existing WCA/derived-mobility pattern.

**IMPLEMENTATION completeness — the 8-state ladder. This is what actually gates the PI's priority, and it is not the same question.** Conditions, in dependency order:

1. **Which connectors must become force-real.** For example (i): `membrane_erm_cortex` (already FORCE-REAL at native — 655,362 tethers, total ≈24,740 pN per the audit table) + `nmii_cortex_motor` (FORCE-REAL) + `surface_porous_transfer` and `membrane_cytosol_boundary` (currently dispatch-only; the native driver deliberately does not re-invoke their force pass) + the new `membrane_cortex_contact` + **cortex/membrane component-local force ownership** (today both alias `cell.pos_d`/`cell.f_d`; `SurfaceBody.__post_init__` already raises "membrane and cortex must have distinct force ownership" but is never constructed outside tests). For example (ii): `lamellipodium_membrane_contact`, `lamellipodium_nascent_fa`, the `alpha2beta1_collagen_series` joint as ONE runtime, `ecm_crosslink` (audit: ECM ran natively at 200–220 fibers with **zero crosslink bonds**), `ecm_far_field_anchor` (needs a non-test caller), `membrane_ecm_contact`.
2. **Does a composed accepted step need one coupled solver? No — but it needs a coupling loop with a residual.** Partitioned/subcycled solves are explicitly allowed and phase re-invocation is contracted (`dispatch.py:322-329`). What does not work is today's single pass: `ComposedNativeCell.solve_candidate` (`composed_native.py:347-359`) zeroes forces, runs `run_candidate()` once, computes motor loads — and never updates a position. The caller-owned `solve` must (a) iterate cross-component coupling to a device residual and (b) AND a convergence flag into `accepted_d`, which `transaction.py:99-105` already accepts. Without this every deformation number is a relaxation transient — which is why the `nmii_sf_motor` magnitude was correctly withheld at residual/tension = 15.5%.
3. **Jacobians or forces?** Forces alone suffice *only if* the loop iterates. Where the coupling stiffness dominates a component's own diagonal (ERM against a membrane node; crossbridge against an SF node), one lagged pass transmits almost nothing. `sf_implicit.py` already demonstrates the correct pattern — a genuinely coupled two-component tangent over concatenated *scratch* with the two authoritative arrays never aliased, and a derived (not tuned) regularizer (:66-72). Recommend a `tangent_required` declaration + an operator-action hook, but book it as contract hygiene, not as the PI question.
4. **Observables.** Add a first-moment (traction dipole) + centroid channel to `GlobalCellLedger` and a translocation scenario to the roadmap. `ecm_world.py:346` already promises a moment the ledger cannot accept.
5. **The one genuine PI gate on this path is a number, and it is a gate contract, not a physical parameter:** the acceptance tolerance for `assemble_balance`. Per the audit, a declared tolerance value "exists nowhere in code or docs." Everything else below can proceed without inventing a rate.
