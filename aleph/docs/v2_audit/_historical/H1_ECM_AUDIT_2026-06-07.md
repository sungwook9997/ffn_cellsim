# H.1 ECM Unit — Construction Audit (2026-06-07)

**Auditor:** auditing subagent (read-only; no code edited, no git mutation)
**Branch:** `h7/full-cell-integration`
**Scope:** Is the H.1 ECM unit built PROPERLY — fine-grained mechanistic per
CLAUDE.md, contract-compliant per the H.1 brief, building/running, and
correctly wired into the cell?

---

## VERDICT: **YES-WITH-GAPS**

The H.1 ECM **as a standalone bulk-rheology module is correctly and faithfully
built**: it is a genuinely fine-grained, mechanistic discrete-fiber Mikado
network (explicit bead particles + harmonic bonds + bending angles + WCA
excluded-volume + cross-link bonds, integrated by the frozen L-M BAOAB), it
honours the architectural principle (no v1 force kernel imported into the
runtime — only the geometry oracle is reused), every sanity gate is documented
and unit-tested, all 60 collectable H.1 tests PASS, and the three KU-1.30
production gates are reported PASS in `outputs/h1/REPORT.md`.

The gaps that keep it from an unqualified YES:

1. **It is NOT wired into the cell.** (Severity: HIGH — but this may be
   by-design for the current H.7 single-cell line; flagged for PI.) The
   cell/FA adheres to **point-particle ligands** held rigid by
   `SubstrateLigandPin`, NOT to the H.1 collagen fiber network. The Mikado
   `actin_ecm` type appears in **zero** cell/bridge code paths.
2. **Cross-links are STATIC harmonic bonds — no binding/unbinding kinetics**
   (no Bell-Evans, no catch-bond, no turnover). (Severity: MEDIUM — see below;
   defensible for collagen permanent cross-links but the brief/CLAUDE.md
   "Bell-Evans force-dependent off-rate" expectation is unmet for the ECM.)
3. **Two acceptance bands were re-anchored away from the brief contract**
   (G_0 [15,200]→[1,50] Pa; stiffening sign flipped). PI-ratified per REPORT,
   but this is a contract change relative to the immutable brief. (Severity:
   MEDIUM — process/provenance, not physics.)

## 1. What the ECM model IS (as built)

| Aspect | Implementation | Evidence |
|---|---|---|
| **Fiber representation** | Explicit discrete beads: N_f fibers × 21 beads, ℓ₀ = 0.5 µm, L_f = 10 µm, R_bead = 50 nm (KU-1.2 collagen). Mesoscopic but per-bead — fully fine-grained. | `mikado.py:434-497` (`_network_to_frame`); `configs/phase1_h1.yaml:38-58` |
| **Network topology** | 2D Mikado (random rods) extruded to z=0 in a 3D-periodic cubic box, ρ_L = N·L_f/L_box², ℓ_c = π/(2ρ_L). Geometry REUSED from oracle `generate_2d_fiber_network` (geometry call ONLY). | `mikado.py:321-338`, `421-431`; `cross_links.py:223-235` |
| **Backbone stretch** | `md.bond.Harmonic`, k = μ/ℓ₀, r0 = ℓ₀ (μ = 8.6e-9 N, KU-1.2). | `mikado.py:341, 546-547` |
| **Bending** | `md.angle.Harmonic`, k = κ/ℓ₀, t0 = π (κ = 7e-26 N·m², KU-1.1). Small-bend match to oracle's (κ/ℓ₀)(1−cos θ). | `mikado.py:342-343, 561-562`; docstring `mikado.py:19-34` |
| **Cross-links** | Harmonic bonds at segment intersections, k_xl = 1e-3 N/m (1 pN/nm, KU-1.28), r0 quantized into 11 bins (50 nm) so construction is near-force-free. Geometry from oracle `generate_cross_links`. | `cross_links.py:137-160, 206-296, 543-557`; band-recipe `cross_links.py:138-146` |
| **Cross-link KINETICS** | **NONE.** Cross-links are permanent static bonds. No Bell-Evans off-rate, no catch-bond, no rebinding/turnover. | grep for `bell_evans / catch / off_rate / unbind / turnover` in `aleph/ecm/` → **0 hits** |
| **Excluded volume (D7)** | `md.pair.LJ` WCA repulsive-only, σ = 2R = 100 nm, ε = 0.5 kT, r_cut = 2^(1/6)σ, `mode="shift"`, on `md.nlist.Tree` (BVH, chosen because cell-list segfaults at L/r_cut ~1800). **ON by default** in config. | `mikado.py:564-577`; `configs/phase1_h1.yaml:120-134` |
| **Integrator** | Custom Leimkuhler-Matthews BAOAB-limit Updater (D3, frozen); `md.Integrator` carries forces only (`methods=[]`). dt = α·τ_min (α=0.1, KU-1.26). | `mikado.py:579-592`; `baoab.py` |
| **Substrate compliance** | Separate `substrate.py`: per-ligand anchor spring (`SubstrateAnchorSpring`, k_sub REQUIRED, no magic default), the finite-stiffness endpoint of the rigid-pin↔gel axis. ADDITIVE, **default-off**. | `substrate.py:294-498`; `cell.py:1510-1527` |

**Mechanistic verdict (CLAUDE.md architectural principle):** **MET for the
network mechanics.** This is a true fine-grained model — every fiber bead,
bond, bending angle, cross-link, and EV contact is an explicit HOOMD
particle/bond/pair. The v1 force kernel (`compute_xl_energy_and_forces`,
`compute_energy`) is correctly **NOT** imported into the runtime (verified:
those imports appear only inside `validation/oracles/` and test/bench scripts),
honouring the "oracles are acceptance-only" hard rule. The only sanctioned
coarse-graining (×40 mesoscopic, 21 beads/fiber) is in force.

**The one mechanism gap vs CLAUDE.md:** the worked-examples table in CLAUDE.md
lists "Bond off-rate → Bell-Evans force-dependent" as the mechanistic
standard. The ECM cross-links have **no off-rate at all** — they are permanent.
For native fibrillar collagen this is physically defensible (collagen
cross-links are effectively permanent on the simulated µs timescale; the
KU-1.30 elastic gates are equilibrium-elastic, not remodeling), but it should
be an explicit PI-ratified scope decision, not a silent omission. The
force-dependent off-rate machinery in this codebase lives in the *adhesion*
clutch / cadherin paths, not the ECM.

## 4. Wiring into the cell / substrate / FA

**The H.1 ECM Mikado is NOT wired into the cell.** Confirmed by:

- `grep "actin_ecm" aleph/cell aleph/bridge` → **0 hits**. The Mikado
  collagen-fiber particle type never enters any cell or FA build.
- The only `ecm/` modules the cell imports are `ecm.substrate.resolve_substrate`
  (`manifest.py:41`), `ecm.equilibrate._softstart_step` (`equilibration.py:85`),
  and `ecm.substrate.{SubstrateAnchorSpring, attach_substrate_spring}`
  (`cell.py:140-142`). The fiber network (`mikado.py`, `cross_links.py`) is
  used only by H.1's own tests + `scripts/h1_wallbench.py`.

**What the FA actually adheres to:** point-particle ligands, one per FA, placed
under each FA centre at z=0 (`bridge/fa.py:436, 471-501`). The integrin→ligand
clutch (catch-bond, S1) forms against these ligands. The ligands are the
"substrate."

**Is the substrate physiologically faithful for the PI experiment (col-I on
rigid glass)?** **YES for rigidity, NO for fiber architecture.**
- Rigidity: default path is `SubstrateLigandPin` (`cell.py:199-258, 1521-1527`)
  — a post-BAOAB position reset that holds each ligand bit-exactly immobile =
  an effectively infinite-stiffness (GPa-equivalent) backing. That correctly
  models col-I-on-rigid-glass (PI condition b). The compliant
  `SubstrateAnchorSpring` (finite k_sub) is the optional gel endpoint and is
  **default-off** (`cell.py:1510` `if p_substrate is not None`, else pin).
- Architecture: the substrate is a flat set of discrete ligand points, NOT a
  compliant col-I fiber mesh. For a *rigid* dish this is an acceptable
  abstraction (the ligand is the integrin-binding site; the fiber elasticity is
  irrelevant when the backing is rigid). For any *compliant ECM / 3D matrix /
  durotaxis / fiber-remodeling* experiment, the cell would need to adhere to
  the actual Mikado network — which is not currently possible.

**Net:** for the present H.7 rigid-substrate single-cell line, the
ligand-pin substrate is a faithful stand-in and the absence of the Mikado is
not a correctness bug. But the H.1 ECM, as a mechanical object, is currently
**orphaned** from the cell — it validates standalone and then is unused. PI
should confirm whether that is intended (ECM is a future-coupling deliverable)
or whether the integrin→fiber path was supposed to land.

## 5. Concrete issues (severity-ranked)

### HIGH

**H-1. H.1 ECM Mikado is not coupled to the cell (orphaned module).**
The collagen fiber network never enters a cell build; the FA adheres to flat
rigid-pinned ligand points instead.
- Evidence: `actin_ecm` absent from `cell/`+`bridge/`; FA ligands at
  `bridge/fa.py:471-501`; pin at `cell.py:1521-1527`.
- Impact: any compliant-ECM, 3D-matrix, durotaxis, or matrix-remodeling
  capability is unavailable; the H.1 elastic validation does not feed the cell.
- Recommend (DO NOT FIX — surface to PI): ratify scope. Either (a) declare
  H.1 a standalone bulk-rheology deliverable + future coupling seam (document
  it as such in the brief/STRUCTURE), or (b) design the integrin→Mikado-bead
  clutch path so the cell can adhere to the fiber network for compliant-ECM
  conditions. The `substrate.py` k_sub spring is a *lumped* compliance proxy,
  not the fine-grained fiber-network coupling CLAUDE.md would prefer.

### MEDIUM

**M-1. Cross-links have no binding/unbinding kinetics (permanent bonds).**
No Bell-Evans off-rate, catch-bond, or turnover on ECM cross-links.
- Evidence: `ecm/` grep for off-rate/catch/unbind/turnover → 0 hits;
  `cross_links.py` builds static `md.bond.Harmonic`.
- Impact: the ECM cannot stress-relax, remodel, or yield via cross-link
  rupture; KU-1.30 is purely equilibrium-elastic, so the gates don't expose
  this. CLAUDE.md's worked-example table sets Bell-Evans as the off-rate
  standard.
- Recommend: PI scope decision. Permanent collagen cross-links are defensible
  for the elastic regime — if accepted, record it explicitly as a ratified
  ECM-scope call (parallel to how adhesion uses catch-bonds). If matrix
  yielding/remodeling is ever in scope, add a force-dependent xl off-rate
  updater mirroring the existing clutch/cadherin Bell-Evans machinery.

**M-2. Two acceptance bands re-anchored away from the immutable brief.**
Brief #1 G_0 ∈ [15,200] Pa → config [1,50]; brief #2 exponent ∈ [−2.5,−1.5] →
config |β| ∈ [1.5,2.5] (sign flipped).
- Evidence: brief `H1_ecm_mikado.md:57-58` vs `configs/phase1_h1.yaml:103,115`.
- Impact: process — the brief is the frozen contract; it was not updated to
  reflect the PI-ratified D4 re-anchor, so brief and config now disagree.
  (The physics derivation behind the re-anchor is sound and documented.)
- Recommend: amend the H.1 brief (or add a ratified-change appendix) so the
  contract and the config agree; this is a doc-consistency fix, not a physics
  change. CLAUDE.md "no gate-loosening" is satisfied in spirit (PI-ratified,
  derived) but the audit trail should live next to the contract.

**M-3. Cross-link energy-oracle gate is a surrogate, not the brief's oracle.**
The brief asks for HOOMD-vs-oracle PE ≤ 1e-6; xl is validated against an
analytical binning prediction instead (the ecm-bond+angle subset IS validated
against the oracle).
- Evidence: `cross_links.py:30-34`; `TestEnergyOracleWithXL`.
- Impact: low — the surrogate is mathematically exact for the binning model and
  the construction-time xl energy is ~0.07 kT/link, but it does not cross-check
  the oracle's xl force form.
- Recommend: optionally add a per-link r0 oracle cross-check via a custom force
  on a small fixture, or have PI ratify the binning surrogate as the xl gate of
  record (already surfaced in M2 closeout per the docstring).

### LOW

**L-1. `effective_E_sub` bridge (k_sub → modulus) is an unratified TODO.**
Returns a stiffness *density* [N/m³], not a Pa modulus; no contact-model
prefactor.
- Evidence: `substrate.py:249-288` (self-flagged TODO, "no gate depends on it").
- Impact: none today (diagnostic only). Recommend: ratify the contact-model
  oracle (flat-punch vs Hertzian) before any k_sub→E_sub claim is used.

**L-2. Topology relies on the v1 oracle's primary-copy-only intersection
finder** (misses ~5% of periodic-boundary crossings).
- Evidence: `cross_links.py:6-7, 114-115`; ±15% count band absorbs it.
- Impact: low (within band, documented). Recommend: note as a known
  finite-size bias; only revisit if z-coordination accuracy is ever tightened.

**L-3. `n_steps_equilibrate/n_steps_sample` in the config (50000) are unused
by the resolver** — production drivers pass their own step counts. Minor stale
config keys. Recommend: prune or document as defaults-for-scripts.
