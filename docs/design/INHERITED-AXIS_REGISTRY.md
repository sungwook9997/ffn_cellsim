# Axis registry — every numeric field in the cell, and whether it is a sweep axis

> **Status: AGENT-PROPOSED.** No `decided_by` field appears here and an agent may not add one. The
> criteria this table serves are agent proposals; an earlier version attributed them to the PI on a
> timestamp-only citation, which `CLAUDE.md` §2 rule 2 does not permit — that attribution is
> withdrawn.

This file is the join between a literature study and a sweep: both read the same list, so evidence
gathered from papers and evidence generated by simulation land on the same coordinates and can be
combined later. The two right-hand columns are deliberately empty and are what external study fills
in. An axis whose `prior range` cell is empty is **not sweepable**.

Companions: `docs/superpowers/specs/2026-08-04-inner-aleph-library-criteria.md` (the criteria),
`docs/design/EXP_LANE_GATES.md` (what the experimental lane needs).

## Nothing is silently dropped

Earlier versions of this table were built by matching field **names** against a regex, and every
defect an audit found came from that: fields whose names the pattern missed were absent with no
trace, and `rest_sepa`**`ratio`**`n_um` was classified `linear` because the substring `ratio` appears
inside `separation`.

The table now lists **every numeric field** on every non-output carrier in `aleph/vertical` and gives
each one a class. A field that is not an axis stays in the table with the reason it is not, so the
next reader checks a judgement instead of trusting an absence.

| Class | Meaning | Count |
|---|---|---|
| **axis** | a value the library sweeps | **125** |
| **topology** | names a node or element, not a value | 27 |
| **numeric** | solver, guard or assay constant — pinned, convergence-verified | 9 |
| **state** | evolves during a run | 8 |
| **discretisation** | subdivides one element between fixed endpoints | 1 |
| **derived** | computed in `assembly.py` from other axes | 1 |
| **split_encoding** | the field that *is* a declared split, so not an axis beside it | 1 |
| | **total rows** | **172** |

Of the 125 axes: 103 log, 17 linear, 5 integer; **78** sit on carriers whose docstrings say the
values are unsourced, and **70** have no default at all and cannot be swept until a prior is declared.

**Multiplicity comes from `aleph.state.parameter_groups.DECLARED_GROUPS`, not from what the builders
ship.** Three carriers split — see the section below — and the count does not move when a scenario
file lands. `scripts/generate_axis_registry.py` emits this table and **refuses** to emit anything if a
numeric law varies by an enum index that nothing declares. Regenerate rather than hand-edit; a control
in `tests/scripts/test_generate_axis_registry.py` fails when this file and the generator disagree.

Bookkeeping counters (`topology_epoch`, `_pending_*`, `accepted_generation`, private
underscore-prefixed fields) and output carriers (`*Report`, `*Measurement`, `*Energy`, `*Result`,
`*Proposal`) are excluded before classification, by rules written in the generator rather than by
hand.

## The multiplicity rule that was withdrawn, and what replaced it

The withdrawn rule was: *a card contributes one axis set per distinct value set the tree ships for
it.* A second adversarial audit broke it three ways, each verified against the tree. It is recorded
here because the replacement is only legible next to what it replaced.

**It cannot see a split the model encodes inside one card.** `ClutchCard` ships a single value set,
so the rule says ×1 — but `maturation_scale = (1.0, 2.0, 4.0)` is documented as a multiplier on
anchor stiffness, one entry per `MaturationState`, and a non-increasing table is **refused** on the
grounds that a maturation state changing nothing would be invisible to every conservation check. The
model asserts three stiffnesses; the rule counts one card. The audit found the same shape in
`Clutch.occupancy` (ligand stiffness is `n·k_bond`, actin is `n·k_anchor·m(state)`), in ECM segment
`damage` (axial modulus scaled by `1−d`), and in NMII `head_activation` (attachment rate scaled by
activation).

**It splits on differences that carry no evidence.** `sf_arc.MaterialCard` is four value sets, but
that carrier's own docstring calls the magnitudes placeholders that "carry no evidence whatsoever".
The `CABLE`/`ROD` element distinction is structural and derived from the contract; the numeric
differences — ventral 1000 against perinuclear 400, dorsal `(800, 10)` against transverse
`(600, 40)` — are independent guesses. `default_collagen_card` is blunter still: "Nothing about these
numbers is sourced." A rule keyed on shipped values turns a placeholder that happens to differ into a
permanent coordinate split.

**Its answer moves when unrelated code lands, and the table did not even match it.** Applied honestly
at HEAD the rule gives `IFMaterialCard` **×3**, not the ×2 this file claimed — there is a third value
set at `aleph/runtime/law_cases.py:5341`, and the ×2 silently excluded the runtime builder. It gives
`FibreCard` **×2**, not ×1: `whole_cell.py` ships a `ROD` card beside `ecm.default_collagen_card`'s
`CABLE` card. Both changed because `7d14ee4` landed a scenario file. **An axis count that moves when
someone adds a scenario cannot be a library's primary coordinate system**, because every stored entry
is indexed against it.

### The replacement — now written up as `docs/decisions/PROPOSAL-declared-parameter-multiplicity.md`

Multiplicity should be **declared beside the carrier, not discovered by running builders**:

- a carrier declares its `parameter_group`s explicitly, and that declaration includes every index a
  numeric law reads out of a card tuple, table or mapping;
- a new builder value does not change multiplicity — it is checked for consistency against the
  declaration;
- a difference between values that carry no evidence does not create a group;
- **fail closed**: if a numeric law varies by state, role or subpopulation and no corresponding group
  or index is declared, registry generation is refused.

This is the idiom the rest of the repository already uses — the census declares component contracts,
`ProtocolManifest` declares its fields, `SweepSpec` declares its axes, and a guard refuses what is
not declared.

**The audit that this rule needs has been done.** Every numeric law in `aleph/vertical` that reads an
enum, state or role index was traced, and it yields exactly three splits: `sf_arc.MaterialCard` ×4 by
`Subpopulation`, `IFMaterialCard` ×2 by `Population`, and `ClutchCard.anchor_stiffness_pn_per_um` ×3
by `MaturationState`. Under those declarations the axis count is **125** and it does not move when a
scenario file lands, because `FibreCard` stays ×1 — `FibreElement` is a law-form switch, not a
declared fibre population. The proposal carries the full table and the cases that deliberately do not
split. Writing the declarations into the code is modelling work, not generation work, and it is what the axis
count waits on.

## The coordinate rule

Choose the coordinate in which the forward map is closest to linear.

- **log** — strictly positive scales whose physics depends on ratios: moduli, stiffnesses,
  viscosities, mobilities, rates, lengths. The default.
- **linear** — bounded fractions, strain thresholds, small exponents, and any **signed** quantity.
  `spontaneous_curvature_inv_um` is linear because it may be negative, and a log axis through zero is
  a different question rather than a rescaling.
- **integer** — counts that a spacing parameter converts into a physical length or density.

Where the rule is ambiguous, measure rather than argue: take the Jacobian of the stored observables
with respect to both `θ` and `log θ` at a few reference points, keep the coordinate with the lower
curvature, and record the measurement in the `citation` cell.

**Open gap.** Several axes carry a current value of exactly `0.0` — edge modulus, ECM bending
rigidity, stress-fibre active tension, nucleoplasm drag, bulk term — and a log ladder cannot reach
zero. The integer rule handles this by making `0` a separate category rather than a bin edge; the
continuous case has no rule yet and needs one before those axes are swept.

## A count is an axis when a spacing parameter gives it a physical size

`node_start` and `node_count` are documented on every filament carrier as naming a contiguous range
that tiles `[0, N)`. So the **number of elements** is the number of records — that is the sector
index — and `node_count` is how finely one element is cut. The test then asks whether that cut also
fixes a physical size:

| Carrier | Spacing parameter | Verdict |
|---|---|---|
| `microtubule.Rod.capacity` | `MicrotubuleCard.rest_spacing_um`, "the lattice spacing of the rod, the rest length of every segment, and the length one growth event adds" | **axis, with a caveat.** `capacity × rest_spacing_um` bounds the rod's length, but the docstring calls `capacity` build-time *array capacity* with the live active-node count held as state, so reading it as a per-cell-type biological maximum is an inference the code does not establish |
| `nmii.RigidActinTrack.site_count` | `site_spacing_um` on the same carrier | **axis.** count × spacing is the track length. Density is set by the spacing, not the count |
| `filopodium.BundleFilament.node_count` | `rest_spacing_um` exists, but on `BundleCrosslink`, where it is the **interfilament** spacing setting bundle thickness | **discretisation.** Lateral, not axial |
| cortex filaments, stress fibres, intermediate filaments, lamellipodium filaments, ECM fibres, lamina envelope | none | **discretisation.** Geometry comes from node positions |

## What is not in this table at all

- **The six population axes** — stress fibre, microtubule, intermediate filament, lamellipodium,
  filopodium and focal adhesion counts. They are the sector index, and their biological ranges are
  sourced blanks in the criteria document.
- **The `ExperimentContextManifest`.** An earlier version listed six field names that **do not
  exist**; the real fields are `context_id`, `temperature_K`, `temperature_evidence`, `medium`,
  `substrate`, `external_fields`, `boundary_conditions`, `osmotic_state`, `schedule`,
  `protocol_controls` and `notes`, of which only temperature is a required scalar and the rest are
  free-form mappings. Context axes will be added when their shape is settled, from the class rather
  than from memory.
- **The nine binary law switches** — `ContactLaw`, `FibreElement`, `DetachmentLaw`, `StrokeModel`,
  `TurgorEnsemble`, `IFResponseClaim`, `DragChannel`, `ExteriorDragChannel`, `TransferCoupling`.
  Discrete model variants, `2⁹ = 512` of them, layered over the continuous axes rather than mixed in.
- **Solver and discretisation controls** — `max_steps`, `force_tolerance_pn`, `subdivision_level`,
  the step-size window. Pinned and convergence-verified, never phenotype axes.

## What an independent audit changed

An adversarial read-only audit by a separate Codex session on 2026-08-04 refuted the previous
headline count and its supporting claims. Everything it found was verified against the tree before
being accepted. What it produced, beyond the corrections listed above, was the multiplicity rule —
its finding was that the rule was missing, and stating it is what makes a count exist at all.

Also corrected in the criteria document: the storage figures had summed three arrays and presented
the result as total stored state. Counting every unique array gives 20.0 / 77.4 / 307.1 KiB at
subdivision levels 1 / 2 / 3, roughly 3.4× the withdrawn figures, and no entry serialiser exists, so
the corpus extrapolation is withdrawn rather than rescaled.

What the audit confirmed and left standing: the cortex-to-membrane 3:1 node ratio at every level; the
fluctuation spectrum's Jacobian rank of 2 with `κ/k_BT` and `σR²/κ` as the visible groups, including
the equipartition control; and every claim in `EXP_LANE_GATES.md` about the `aleph/learn` lane gates
and authority ceilings.
